# 后端开发交接：任务归档

## 需求摘要

为任务管理工具增加“任务归档”。归档任务默认不出现在普通任务列表，但仍可查询和恢复。普通成员只能归档自己负责的任务，项目管理员可以归档和恢复项目内任务。归档任务默认不允许继续普通编辑。

## 建议接口

| 方法 | 路径 | 用途 | 权限 | 备注 |
| --- | --- | --- | --- | --- |
| `POST` | `/tasks/{task_id}/archive` | 归档任务 | 任务负责人或项目管理员 | 独立动作接口，便于权限和审计 |
| `POST` | `/tasks/{task_id}/restore` | 恢复任务 | 项目管理员 | 仅允许恢复已归档任务 |
| `GET` | `/tasks?archived=true` | 查询归档任务 | 项目成员或项目管理员，待确认 | 默认 `GET /tasks` 应排除归档任务 |
| `PATCH` | `/tasks/{task_id}` | 修改任务 | 按现有规则 | 已归档任务默认拒绝普通编辑 |

## 权限规则

- 非项目成员不能查看、归档或恢复任务。
- 普通成员只能归档自己负责的任务。
- 项目管理员可以归档和恢复项目内任务。
- 恢复、修改负责人等高权限操作只能由项目管理员执行。
- 权限必须在后端校验，不接受前端隐藏按钮作为权限方案。

## 数据变更提醒

- 确认 `status` 是普通字符串、应用 enum，还是数据库 enum。
- 如需记录归档时间和归档人，建议确认 `archived_at`、`archived_by`。
- 如需恢复到归档前状态，可能要记录归档前状态。
- 如果任务量大，确认 `archived` 筛选是否需要索引。
- 如果已有历史归档数据，评估 backfill（补齐历史数据）。

## 错误码与状态码

| HTTP 状态码 | 错误码 | 场景 |
| --- | --- | --- |
| `400` | `invalid_task_state` | 当前状态不允许归档或恢复 |
| `401` | `unauthenticated` | 未登录 |
| `403` | `forbidden` | 无权操作该任务 |
| `404` | `task_not_found` | 任务不存在或不可见 |
| `409` | `task_already_archived` | 任务已经归档 |
| `409` | `task_not_archived` | 任务未归档，不能恢复 |

## 测试建议

- 普通成员归档自己负责的任务成功。
- 普通成员归档别人负责的任务失败。
- 项目管理员恢复归档任务成功。
- 非项目成员不能查看或操作项目任务。
- 归档任务不出现在默认任务列表。
- `archived=true` 能查到归档任务。
- 已归档任务不能通过普通编辑接口修改。

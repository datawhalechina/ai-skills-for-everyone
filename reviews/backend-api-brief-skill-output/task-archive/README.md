# Backend API Brief 试跑：任务归档

测试日期：2026-05-26

## 测试目标

验证 `skills/backend-api-brief/SKILL.md` 是否适合小白用户：用户只提供一段业务需求，不知道后端怎么做，Skill 能否生成一份自己能看懂的接口说明和一份开发可读的后端交接稿。

## 输入

- [小白原始需求](inputs/api-request.md)

## 输出

- [给自己看的接口说明](outputs/api-explainer.md)
- [后端开发交接稿](outputs/backend-handoff.md)

## 初步观察

优点：

- 没有直接写代码或生成生产 SQL，边界比较安全。
- 输出能把“任务归档”从一句需求拆成权限、状态、接口、数据变更和测试点。
- 优化后改成两份主文档：一份给自己看，一份给开发看。
- 风险检查融进两份文档里，不再额外生成第三份文档增加负担。

需要继续打磨：

- 如果用户需求更模糊，Skill 需要先问 3-5 个问题，而不是直接输出。
- 后续可以补一个固定 starter，让用户把需求放进 `inputs/api-request.md`。
- 可以再增加一个“只输出给自己看的解释”的极简模式。

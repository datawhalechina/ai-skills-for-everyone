# 让普通人也能用上开源 Skill

很多开源 Skill 很强，但普通人打不开门。GitHub、Python、API key、Agent、命令行、依赖安装，这些词放在一起，已经足够把大多数人劝退。

所以这个项目不能只做“收录”，也不能只写“上手指南”。我们要把强但硬的 Skill，包装成普通人能走完、最好能反复使用的工作区。

## 四层内容

每个值得推荐的大 Skill，尽量拆成四层：

### 1. 场景入口

用户先看到任务，不先看到仓库名。

好的入口是：

- 我想把 PDF 做成 PPT。
- 我想把会议录音整理成纪要。
- 我想把一周工作记录变成周报。
- 我想把表格数据变成分析报告。

不好的入口是：

- 这里有一个 Agent workflow。
- 这里有一个 prompt pack。
- 这里有一个 Python 项目。

### 2. 普通人上手指南

这是给非技术用户看的页面。它不讨论源码结构，先告诉用户怎么完成一件事。

一篇上手指南要回答：

- 这个 Skill 能帮你做什么。
- 你要准备什么材料。
- 你需要安装什么工具。
- 大概会花多久。
- 会不会花 API 钱。
- 数据会不会发给模型。
- 最短路径怎么跑。
- 可以直接复制给 Agent 的提示词是什么。
- 常见问题怎么处理。

### 3. 技术档案

这就是 `catalog/`。它记录来源、许可证、stars、维护状态、安装方式、优点、限制和风险。

普通用户不一定要读完技术档案，但我们必须保留这些信息。否则推荐就没有根。

### 4. 开箱 Kit

这就是 `kits/`。它不是说明书，而是一个预置工作区：输入目录、输出目录、样例材料、可复制提示词、环境检查脚本和故障排查。

普通人能不能真的用上，主要看这一层。

## 上手难度标签

每个 Skill 都要标清楚上手难度。

| 标签 | 含义 |
| --- | --- |
| 直接可用 | 打开网页、安装插件或复制提示词就能试。 |
| Agent 可用 | 需要 Trae、VS Code Copilot Agent、命令行型 Agent 这类工具。 |
| 本地安装 | 需要 Python、Node、命令行或本地依赖。 |
| 开发者友好 | 普通人不建议直接上手，但适合开发者改造。 |

一个 Skill 可以有多个标签。比如 PPT Master 可以标成：`Agent 可用`、`本地安装`、`进阶`。

## 开箱即用包

每个推荐 Skill 最好配一个“开箱即用包”。它不只是文档，还应该包含：

- 一页普通人上手指南。
- 一段可复制提示词。
- 一个最小测试材料。
- 一个预期输出说明。
- 一个常见问题区。
- 一个隐私和版权提醒。
- 一个固定输入目录。
- 一个固定输出目录或清楚的输出位置说明。
- 一个环境检查脚本。

如果安装复杂，还要加一段“请懂技术的朋友帮你做这几步”。这听起来不酷，但很真实。普通人不需要理解所有依赖，只需要知道卡在哪里、找人帮忙时该说什么。

## 三种低成本路线

复杂 Skill 不一定要让每个用户都亲自安装。可以按门槛拆成三条路线：

### 自己安装

适合已经会用 Agent、能运行命令的人。指南要给最短路径，但不要把原项目 README 复制一遍。

### 找人安装一次

适合大多数普通用户。指南要提供一段可以发给同事、朋友或技术支持的请求，明确让对方帮忙完成哪些事。

用户之后只需要：

- 把材料放到固定文件夹。
- 复制提示词。
- 找导出的结果。
- 检查内容。

### 团队共享工作区

适合公司、社团、课程小组。一个懂技术的人维护安装和模板，其他人按固定说明使用。

这条路线尤其适合 PPT、会议纪要、文档摘要、表格分析这类高频办公 Skill。

## 对 PPT Master 的应用

PPT Master 很适合做第一个 Skill Kit。

用户看到的入口应该是：

> 低成本用 PPT Master 把 PDF 变成可编辑 PPT

而不是：

> 一个 AI-driven multi-format SVG content generation system

指南里应该写清楚：

- 需要 Python 3.10+。
- 需要一个能读写文件、运行命令的 Agent 工具。
- 可以用 PDF、DOCX、URL、Markdown 或直接粘贴文本。
- 输出是 `.pptx`。
- 高质量结果依赖模型能力。
- 公司机密材料要谨慎，因为内容会进入模型上下文。
- 第一次只做 3 到 5 页小样，先验证流程，别一上来跑正式大项目。

Kit 里应该准备好：

- `inputs/`：用户把 PDF、DOCX、Markdown 放这里。
- `prompts/normal-use.txt`：用户直接复制给 Agent。
- `samples/sample-source.md`：第一次测试用的小材料。
- `scripts/check-env.ps1` 和 `scripts/check-env.sh`：检查 Python、Node 和关键目录。
- `START_HERE.md`：只写最短路径。

更详细的设计见 [开箱即用 Skill Kit](one-click-skill-kit.md)。

## 我们的判断标准

一个 Skill 只有在我们能写出“普通人上手指南”，并且能设计出一个基本可用的 Skill Kit 时，才算真正进入推荐区。

如果只能写技术档案，说明它还停留在“开发者可参考”。这也有价值，但不要把它包装成普通人开箱即用。

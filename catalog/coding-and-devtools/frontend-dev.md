## 一句话说明

`frontend-dev` 是一个高视觉前端 Skill，强调首页、营销页、产品页、动效、文案和本地媒体资产工作流。

## 适合谁

- 想做首页、营销页、产品页的人。
- 想要更强视觉冲击和动效表达的人。
- 能处理 API Key、资产生成、依赖安装和工程检查的进阶用户。

## 典型场景

- 产品首页。
- 营销落地页。
- 高视觉展示页。
- 强动效品牌页面。

## 怎么使用

最短路径：

1. 把 `frontend-dev` 的 `SKILL.md` 安装或复制到 Agent 可读取的位置。
2. 明确页面类型、品牌调性、目标用户和内容结构。
3. 如果要生成图片、视频、音频等媒体资产，先配置 MiniMax API Key，并逐条确认资产生成提示词。
4. 生成页面后检查本地资产、动效性能、移动端和可访问性。

## 示例输入

```text
请使用 frontend-dev，帮我做一个 AI Skill Hub 的首页。

要求：
- 视觉要像产品首页，而不是后台页面。
- 强调“找到能跑起来的 Skill，而不是收藏更多链接”。
- 有新手路线、Agent 熟手路线、贡献路线。
- 不使用外链占位图。
```

## 预期输出

- 更像首页或营销页的视觉方案。
- 更强的动效、文案和视觉叙事。
- 如果配置完整，可以生成并引用本地媒体资产。

## 优点

- 很适合首页、产品页和营销页。
- 文案、动效和视觉表达更强。
- 有质量门禁，强调本地资产和性能约束。

## 限制

- 对内部工具台可能太重、太视觉化。
- 完整媒体资产流程依赖 MiniMax API Key。
- 对普通用户不是第一入口。

## 风险和注意事项

- 生成媒体资产前必须确认提示词和用途。
- 注意 API 调用成本和素材版权边界。
- 工具型页面要克制动效，不要影响阅读和操作效率。

## 结论

推荐作为“前端页面 / 小应用生成”的高级视觉补充。做首页、营销页、产品页可以优先看它；做内部页面不一定优先。

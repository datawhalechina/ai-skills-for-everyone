# 周报 starter 常见问题

默认会生成两份文件：

```text
outputs/leader-summary.md
outputs/weekly-report.md
```

如果只生成了其中一份，可以追加：

```text
请补齐两份 Markdown 输出：领导版摘要保存到 outputs/leader-summary.md，完整周报保存到 outputs/weekly-report.md。
```

## 生成结果太像模板

可以追加这句：

```text
这版太像模板了。请保留事实不变，改得更像真实员工写给主管看的周报，少用套话。
```

## 它编造了不存在的进展

可以追加这句：

```text
请重新生成。只能使用 inputs/ 里明确出现的信息，不要编造数字、日期、结论和承诺。不确定的内容放进“待确认”。
```

## 它把进行中写成已完成

可以追加这句：

```text
请把“已经完成”和“仍在推进”重新区分。只有输入里明确完成的事项才能写成已完成；仍需确认、补齐、复核的事项请放到风险、下周重点或待确认里。
```

## 风险写得太像问题清单

可以追加这句：

```text
请重写“风险与判断”。每条风险都要写清楚：问题是什么、会影响什么、下一步怎么处理或需要谁确认。
```

## 输出太长

可以追加这句：

```text
请压缩到 500 字以内，保留事实和风险，不要展开背景。
```

## 输出太短

可以追加这句：

```text
请稍微展开一点，每个部分至少写 2 到 3 条，但不要新增输入里没有的信息。
```

## 语气不适合发给领导

可以追加这句：

```text
请改成适合发给直属领导看的版本：语气稳重、简洁，突出进展、风险、下周计划和需要支持的事项，不要太口语，不要邀功，也不要把问题写成甩锅。
```

## 输入信息太乱

先不要急着让 Agent 写周报。把材料按下面几类粗略分一下：

```text
本周完成：
进行中：
风险 / 阻塞：
下周计划：
需要协作：
```

哪怕每类只有几条短句，也比一整段聊天记录更稳定。

## 涉及敏感信息怎么办

先手动替换：

```text
客户真实姓名 -> [客户A]
公司内部项目名 -> [项目B]
金额 -> [金额已脱敏]
账号 / 手机号 / 邮箱 -> [账号信息已脱敏]
```

不要把客户名单、合同、报价、账号密码放进输入文件。

# Backend API Brief starter 常见问题

默认会生成两份文件：

```text
outputs/api-explainer.md
outputs/backend-handoff.md
```

如果只生成了其中一份，可以追加：

```text
请补齐两份 Markdown 输出：给自己看的接口说明保存到 outputs/api-explainer.md，后端开发交接保存到 outputs/backend-handoff.md。
```

## 生成结果太像技术方案

可以追加这句：

```text
请重写 outputs/api-explainer.md，让没有后端经验的人也能看懂。少写 endpoint 细节，多解释这件事为什么需要后端、权限和状态。
```

## 开发交接稿太空

可以追加这句：

```text
请补强 outputs/backend-handoff.md：接口清单、权限规则、错误码、数据变更提醒、测试建议和待确认问题都要能让开发继续评审。
```

## 它编造了不存在的规则

可以追加这句：

```text
请重新生成。只能使用 inputs/ 里明确出现的信息，不要编造角色、字段、页面、接口、日期、负责人和业务规则。不确定的内容放进“待确认”。
```

## 它把权限写成前端控制

可以追加这句：

```text
请重写权限部分。权限判断必须发生在后端；前端隐藏按钮只能作为体验优化，不能作为安全边界。
```

## 它开始写代码或 SQL

可以追加这句：

```text
请停止实现代码。这个 starter 只做后端规划和交接，不生成生产 SQL、不写 migration、不改数据库。请把数据结构变化写成提醒和待确认问题。
```

## 待确认问题太多

可以追加这句：

```text
请把待确认问题按优先级压缩成 5 个以内，优先保留会影响权限、数据状态、兼容性、上线风险和开发排期的问题。
```

## 输出太长

可以追加这句：

```text
请压缩两份文档，保留关键接口、权限、状态、风险和待确认问题，不要展开背景。
```

## 输入信息太乱

先不要急着让 Agent 写接口说明。把材料按下面几类粗略分一下：

```text
功能目标：
使用角色：
操作流程：
权限规则：
数据状态：
查询 / 列表：
成功和失败：
待确认：
```

哪怕每类只有一两句话，也比一整段聊天记录更稳定。

## 涉及敏感信息怎么办

先手动替换：

```text
客户真实姓名 -> [客户A]
公司内部项目名 -> [项目B]
金额 -> [金额已脱敏]
账号 / 手机号 / 邮箱 -> [账号信息已脱敏]
内部系统真实地址 -> [内部系统]
```

不要把客户名单、合同、报价、账号密码、密钥、生产数据库信息放进输入文件。

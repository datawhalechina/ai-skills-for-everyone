# 第 4 课：把自己的重复工作搓成 Skill

这里的“搓 Skill”，不是让你立刻写代码。

普通人可以先做一个很小的工作流 Skill：把一件反复发生的事，整理成固定输入、固定步骤、固定输出、样例和提示词。下次再做，就不用重新解释。

## 先说清楚：不建议急着开源

这一课不是教你把自己的经验公开出去。更稳的目标是：先做一个给自己用的本地 Skill。

如果这个 Skill 里面有你真正靠工作经验攒出来的东西，先不要开源。

比如：

- 你做销售多年总结出来的客户判断方法。
- 你做运营时沉淀的活动复盘框架。
- 你处理项目风险、报价、投标、交付、客服、财务、法务时形成的经验流程。
- 你所在公司内部真实使用的 SOP、检查清单、话术、模板和判断标准。
- 你根据真实客户、真实项目、真实数据调出来的提示词。

这些东西不是普通资料。它们可能是你的职业经验、公司的内部方法，甚至是你以后吃饭的本事。

更稳的做法是：

- 自己用的版本留在本地，不要上传到公开仓库。
- 如果想分享，只分享脱敏后的通用版。
- 删除公司名、客户名、项目名、价格、数据、账号、内部流程和真实案例。
- 把“我的独家判断”改成“普通人也能理解的通用步骤”。
- 真要公开前，先确认不违反公司制度、客户保密、合同约定和版权要求。

简单说：可以分享框架，不要轻易公开你的真经验。  
你可以教别人怎么做一个周报 Skill，但没必要把自己多年总结出来的业务判断全放出去。

## 这节课最后会得到什么

你会得到一个这样的文件夹：

```text
my-skill/
├── START_HERE.md
├── inputs/
│   └── put-your-files-here.md
├── prompts/
│   └── normal-use.txt
├── samples/
│   └── sample-input.md
└── outputs/
```

这已经是一个最小可用的 Skill 工作区。

如果你想先看一个成品，可以看本项目维护的：

- [Weekly Status Skill](../skills/weekly-status/SKILL.md)
- [Weekly Status Starter](../kits/weekly-status-starter/README.md)

它就是把“周报”这个窄任务做成轻 Skill，再配一个普通人能直接复制提示词使用的 starter。现在这个样板会同时生成领导版摘要和完整周报，重点不是重新排版流水账，而是帮读者判断当前状态、风险和下一步动作。

## 第 1 步：选一个很窄的任务

不要做“全能办公助手”。

先选这种任务：

- 把一周工作记录整理成周报。
- 把会议笔记整理成纪要。
- 把客户反馈整理成分类和建议。
- 把表格数据整理成一页分析报告。
- 把一段口语草稿改成得体邮件。

任务越窄，越容易做成。

## 第 2 步：写清楚输入

输入就是你要交给 Agent 的原材料。

比如周报 Skill 的输入可以是：

```text
本周任务记录
项目进展
本周目标
当前阶段
遇到的问题
问题带来的影响
下周计划
需要谁确认或支持什么
```

把这些写进：

```text
inputs/put-your-files-here.md
```

## 第 3 步：写清楚输出

不要只写“帮我整理一下”。

要写成这样：

```text
请输出两份 Markdown：
1. outputs/leader-summary.md：给领导快速浏览的摘要。
2. outputs/weekly-report.md：完整周报。

周报要先给出当前状态和本周结论，再展开关键进展、风险与判断、下周重点、需要协作和待确认事项。

不要编造输入里没有的信息。风险要写清楚影响和下一步处理方式。
```

输出越明确，Skill 越稳定。尤其是周报这种场景，不能只要求“整洁好看”，还要明确它要帮助读者做什么判断。

## 第 4 步：写 normal-use.txt

在：

```text
prompts/normal-use.txt
```

放一段以后可以反复复制的提示词。

比如：

```text
请读取 inputs/ 里的材料，生成领导版摘要和完整周报。

要求：
- 不要编造没有出现的进展。
- 不确定的信息标出来。
- 先写当前状态和本周结论，再写关键进展、风险与判断、下周重点、需要协作。
- 风险要写清楚影响和下一步处理方式，不要只列问题。
- 需要协作时写清楚谁要确认什么。
- 语气自然，像真实的人写给直属领导看的，不要像套模板。
- 如果输入信息不够，先问我 3 个以内的问题。
```

## 第 5 步：准备一份假样例

不要拿正式材料做第一次测试。

先在：

```text
samples/sample-input.md
```

写一份假的输入。比如虚构一个项目、一周任务和几个问题。这样你可以放心调提示词。

## 第 6 步：跑一次，改一次

把 `samples/sample-input.md` 复制到 `inputs/`，然后把 `prompts/normal-use.txt` 发给 Trae Agent。

看输出结果：

- 有没有乱编。
- 结构清不清楚。
- 语气像不像人写的。
- 有没有先说清楚当前状态和本周结论。
- 风险有没有写出影响和下一步处理方式。
- 需要协作的事项有没有对象和期望结果。
- 有没有遗漏重要信息。
- 有没有问太多没必要的问题。

不满意就改提示词。普通人做 Skill，核心其实就是这个循环：跑一次，改一次，再跑一次。

## 什么时候需要升级

如果只是自己用，文件夹 + 提示词就够了。

如果你想给别人用，先做脱敏版，再慢慢补：

- `START_HERE.md`：别人怎么开始。
- `troubleshooting.md`：常见问题。
- `scripts/`：能自动检查环境的小脚本。
- `README.md`：这个 Skill 是干什么的。
- 许可证和来源说明。

等到流程稳定、很多人都要用，再考虑写真正的 `SKILL.md` 或做成开源项目。

## 本课练习

先做一个“周报 Skill”。

不用写代码，只建文件夹、写样例、写提示词。  
如果它能稳定把你的零散记录变成一份像样的周报，它就已经有用了。

做完以后，可以对照 [Weekly Status Starter](../kits/weekly-status-starter/README.md) 看看还缺不缺 `START_HERE.md`、样例、常见问题和输出目录。
